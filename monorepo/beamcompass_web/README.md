Self-contained HTML reports for BeamCompass Elixir/OTP architecture analysis.

## Overview

Part of [BeamCompass](https://github.com/nshkrdotcom/beamcompass), a conservative
Elixir/OTP architecture navigator using non-executing source AST inspection.
Dynamic dispatch, transitive effects and runtime behavior remain outside the
current analysis guarantees.

## Getting started

Requires Elixir 1.20.5 or later and a compatible Erlang/OTP release.
From this application's directory:

```sh
mix deps.get
mix compile
```

## Usage

```sh
mix beamcompass.report ../../fixtures/ledger_sample --out /tmp/beamcompass.html
```

This application retains standalone static HTML reports and includes an
implementation of a Phoenix/LiveView navigator. Actual LiveView acceptance and
Mix quality gates must run locally before its P05 runtime is considered verified.

## Documentation

```sh
mix docs
```

The documentation menu includes this guide, API modules, Mix tasks, the
[changelog](CHANGELOG.md), and the [MIT license](LICENSE).

## Packaging

Build the Hex archive with:

```sh
MIX_ENV=prod mix hex.build
```

Development uses the sibling core application when available. Production and
standalone installs resolve `beamcompass_core` from Hex; publish the core package
before publishing this package.

## P05 — standalone Phoenix/LiveView source navigator (implementation pending local verification)

`/navigator` is a source-only LiveView shell and TypeScript semantic stage built
from a **versioned core-generated navigator view**, not from UI-side behavioral
inference. Lenses (behavior/effects/state/failure), bounded semantic zoom,
source/evidence inspection, exact URL identity, keyboard focus and explicit
projection omissions/unknowns are driven by `BeamCompass.Analysis.Navigator`.
A missing snapshot or object does not silently substitute similar source records.
Nothing in this interface executes inspected target Mix projects or macros, nor
claims observed message delivery, effect execution, exact source end ranges,
negative proof or Grand approval semantics.

To build using trusted core/web checkouts and a saved validated source v2 JSON:

```sh
cd monorepo/beamcompass_web
mix deps.get
mix compile --warnings-as-errors
cd assets
npm install --no-audit --no-fund
npm run check
npm run build
cd ..
export BEAMCOMPASS_NAVIGATOR_SNAPSHOT=/absolute/path/to/snapshot-v2.json
export BEAMCOMPASS_WEB_SERVE=1
export BEAMCOMPASS_SECRET_KEY_BASE="$(python3 -c 'import secrets;print(secrets.token_urlsafe(72))')"
mix phx.server
# Browser: http://127.0.0.1:4115/navigator
```

The HTTP server defaults to disabled, and an explicitly enabled server listens
on loopback only with a supplied secret. Optionally set
`BEAMCOMPASS_NAVIGATOR_CATALOG` to a trusted directory of exported v2 snapshots
named `<snapshot_id>.json` (each exact same-project and validated). The revision
navigator never remaps selections by a similar label and rejects symlinks or
unknown revisions. Evidence lineage is supplied as exact core links, not guessed
from client-side text. `assets/package-lock.json` and
`priv/static/app.js` must be generated by the actual local `npm install/build`
step; no verified bundle was produced in the A archive environment because
registry access was blocked. Do not treat the raw TypeScript file as a passing
LiveView browser integration test. The v1 `mix beamcompass.report` static
HTML generator above is preserved independently of LiveView and Grand.

Headless core CLI (no web dependency):

```sh
cd monorepo/beamcompass_core
mix beamcompass.navigator /absolute/path/to/snapshot-v2.json \
  --query 'lens=effects&budget=32&selected_kind=entity&selected_id=EXACT_ID' \
  --out /tmp/beamcompass-navigator-view.json
```

Local gate runner: `scripts/verify_p05.sh` runs trusted Mix quality gates in
both siblings, builds LiveSocket assets, exports a freshly scanned v2 fixture,
checks independent schema/headless consumption, launches actual Phoenix, and
runs actual Chromium browser/headless/deep-link/keyboard/negative-source tests.
It fails closed when runtime tools or dependencies are missing; evidence from
its execution must be recorded by local P05B before any runtime marker moves.
